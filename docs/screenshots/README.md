# Dive screenshots and demo recording

Two Maven profiles in the `cli` module run `hardwood dive` headlessly via
TamboUI recording, each driven by a scripted tape of key presses, and overwrite
the files the CLI reference page shows under `docs/content/assets/cli/`:

| Profile | Tape | Input file | Writes |
|---|---|---|---|
| `screenshots` | `docs/screenshots/dive-screenshots.tape` | `cli/src/test/resources/dive_screenshots_fixture.parquet` | the SVG screenshots named in the tape's `Screenshot` lines |
| `dive-demo` | `docs/screenshots/dive-demo.tape` | the Overture Maps places file | `dive-demo.cast`, played by the self-hosted asciinema player |

## Screenshots

The fixture is generated by `tools/simple-datagen.py` alongside the rest of the
checked-in test corpus. Regenerate it (run from the project's pinned virtualenv,
per [CONTRIBUTING](../../CONTRIBUTING.md) — the checked-in bytes depend on the
pinned PyArrow; this rewrites every generated fixture, not just this one):

```bash
source .docker-venv/bin/activate && python tools/simple-datagen.py
```

Run:

```bash
script -qec "./mvnw -pl cli -am -Pscreenshots package -Dquick" /dev/null
```

Override fixture path:

```bash
script -qec "./mvnw -pl cli -am -Pscreenshots package -Dquick -Dscreenshots.parquetFile=/absolute/path/to/file.parquet" /dev/null
```

## Demo recording

The recording walks Overview → Footer & indexes → Schema → Row groups → row
group #5's `websites.list.element` chunk → Pages and a data page's header →
Dictionary → Data preview and the 5th row. It reads the Overture Maps places
file the performance tests use. Download it once:

```bash
./mvnw -Pperformance-test -pl performance-testing/test-data-setup generate-test-resources
```

The downloader fetches the current Overture release, so the sizes and row
counts in a new recording follow whichever release was downloaded.

Run:

```bash
script -qec "./mvnw -pl cli -am -Pdive-demo package -Dquick" /dev/null \
  && python3 tools/dive-demo-captions.py docs/screenshots/dive-demo.tape docs/content/assets/cli/dive-demo.cast
```

The second command adds the tape's `# @caption` lines to the recording as
asciicast markers, which the player shows as chapters on its progress bar and
the CLI reference page shows in a caption bar below the player. It also
shortens any pause longer than 4 s to 4 s. It cannot run as part of the profile:
the tape ends by quitting `dive`, which exits the Maven JVM. The captions are
user-facing documentation that `docs-prose-check.py` does not scan, so review
them by hand against the prose rules.

`-Ddemo.parquetFile=/absolute/path/to/file.parquet` records against another
copy of the file. A different file changes which column sits where, so the
tape's cursor moves may then land elsewhere.

## Notes

- Both profiles drive `dive` through `exec:java`, and `dive` refuses to start
  unless stdout is a TTY. `script` (from `util-linux-script`, installed in the
  dev container) runs the build attached to a pseudo-terminal; `-q` drops its
  banner, `-e` propagates the build's exit status, and the typescript goes to
  `/dev/null` because only the terminal is wanted. On a normal interactive shell
  the bare `./mvnw …` command works too.
- Existing files are overwritten in place.
- Both profiles set `-Dhardwood.dive.truecolor=true`, so the output carries the
  Solarized palette regardless of the recording terminal's `$COLORTERM`.
- The recorder captures the screen buffer, not the process's output, so JVM
  warnings printed to the terminal do not reach the recording.
- A tape addresses entries by cursor moves, and `dive`'s cursor stops on every
  row, including disabled drill-menu entries. A change that adds, removes or
  reorders rows on a screen the tape passes through can send the walk to the
  wrong screen without failing the build: check the regenerated output.
